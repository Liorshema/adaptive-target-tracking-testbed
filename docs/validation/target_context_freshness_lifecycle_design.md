# Target context, input freshness and launch ownership: frozen design

Baseline: `target_context_freshness_lifecycle_baseline.json` (1,597 pre-existing files). Prior M02/M03/M08 reports, current owners and original dirty tree inspected. No staging/commit/push. This note precedes production edits. User authorization to implement without repeated approvals applies.

## Confirmed causes and evidence

- `tracking_loss_context_test.py` reproduces the absorbing historical cursor. `TimeStepper.advance` builds an immutable candidate, but an unavailable frontier discards all substeps. Simulation retries the original cursor; bounded source histories eventually evict it. Missing old context is checked before stepping and can return forever without a fault. The initiating arrival loss in old physical recordings remains unknown.
- Real baseline cycle in `results/target_context_lifecycle_before`: root-only SIGINT leaves an owned Gazebo server alive after 12 s even though launch exits 0. The included ros_gz launch uses shell=True; the shell/Ruby command is supervised instead of its server child. Scoped runner cleanup recovers the orphan. No unrelated simulation existed initially.
- Localized consensus requires >=.30 s evidence, while control robot age is .20 s. Those holds are legitimate, not timeout errors. Prior 5 Hz health cannot precisely attribute every gap. No justification to weaken either policy or change controller algorithms.
- Control callbacks currently clear a newer valid cache when an older/duplicate message arrives. This is avoidable interruption, but a fix must retain current-source freshness, validation and clock reset. Command replay protection belongs to actuation and stays unchanged.

## State/time contract and minimal changes

Target dynamics remain dx/dt=f(x,u,physical context,t), original RK4/dt/step budget. Every substep uses latest sample s<=t with 0<=t-s<=source.max_age. Physical history is source ordered; bounded out-of-order observations inside retained history can repair a temporary hole. Duplicates do not replace samples. Epoch rollback clears both histories and target state, and invalidates old async replies. Future samples are never eligible for integration. The initial design rejected ahead-of-clock arrivals; the qualification refinement below corrects that ingress policy.

Add an explicit unavailable-context exception and optional partial stepping: completed substeps may be returned, but only become committed/published after Gazebo acknowledges that candidate pose. No dynamics or timestamp relabeling. Missing frontier with no progress publishes nothing, allowing the existing .5 s prediction age to expire. Retry while the past is recoverable. When cursor age exceeds the existing dt*max_steps lookback, or the pose request exceeds that same simulation-time budget, raise an explicit terminal run fault. Launch supervision then shuts the entire pipeline down. No automatic convenient-state restart or teleport; a fresh explicit launch is a new experiment. **Automatic continuous recovery across an irrecoverable gap is not claimed**; complete automatic recovery remains CONDITIONAL. A silent hold/rebase would change trajectory physics and require an epoch-aware observation protocol that this focused task will not invent.

Bound history storage by both time and configured capacity derived at the owner from history duration and maximum possible simulation sample rate (physics step). The existing history duration remains step budget plus source freshness; do not arbitrarily enlarge it.

Correct Gazebo launch ownership by using the vendor executable without an intervening shell; qualify actual descendants before deciding any scoped fallback is necessary. Essential process exit requests shutdown through ROS launch events; optional visualization is not an essential process. Reuse existing runner ownership marker/session/create_time safeguards. Runner requests root SIGINT first, then only signals verified descendants if launch supervision fails within its bounded deadline. Record phase, identities, exit and survivor evidence. No machine-wide cleanup.

Control retains .20 s robot/.50 s prediction ages, .01 s future tolerance, .25 s selected lookahead, source stamps and trust withholding. Ignore validated duplicate/older observations without evicting a fresh newer cache; stale current caches still fail normal validation. Reset clears all caches/session. Add source ages/presence to existing control telemetry for exact per-decision age evidence; no new diagnostic node. Estimation and predictor math/policies stay unchanged. Safely handle repeated shutdown through rclpy.try_shutdown.

## Alternatives and limits

Reject future context, unlimited catch-up/history, stale rebroadcast with fresh stamp, target initial-condition reset, enlarged timeouts and changes to localization consensus. Partial progress preserves the scientific trajectory; terminal failure preserves evidence when continuity cannot be established. Source/graph discovery is asynchronous, so pair graph checks with exact process identity. Graph absence alone cannot prove cleanup. Isolated ROS domain and Gazebo partition prevent unrelated interference; five qualification cycles reuse both to expose cross-cycle leakage.

## Qualification refinement: topic arrival before local clock

The first final five-cycle attempt stopped at cycle3 with an explicit gap fault (cursor1.394s, clock11.396s), no target observations, and zero survivors. Base and joint streams continued; the initiating exact node-local callback order was not recorded. Two red callback tests confirm that valid physical/TF source data arriving just before its local clock update are permanently discarded by the old ingress guards. This supplies a deterministic causal initiating sequence in addition to the absorbing-cursor mechanism.

Correction: retain bounded ahead-of-clock arrivals in the existing source history, but select only source<=integration-time<=clock with the unchanged maximum sample age. Source receipts more than one existing source-age budget ahead of local clock are rejected as incompatible; there is no future-data integration tolerance. Eviction anchors to receipt clock instead of ahead-of-clock source time, preventing a future sample from evicting required past context. Capacity includes the bounded ingress interval as well: ceil((lookback+2*max_source_age)/physics_step)+2=5,302 in D. History duration, numerical integration and safety thresholds do not increase. Rollback clears all pending/retained samples. The margin is an ingress storage bound derived from existing source timing, not permission to use a future pose. Exactly timed old-epoch data within an indistinguishable new source epoch cannot be identified without a richer source protocol; this limitation already applies to the original timestamp-only interfaces.
